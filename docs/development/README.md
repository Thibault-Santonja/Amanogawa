# Guide développeur

Documentation d'onboarding pour contribuer au code d'Amanogawa. Le code reste la source de vérité ; ces documents donnent le contexte et le parcours d'entrée.

## Parcours d'onboarding

À lire dans l'ordre pour prendre le projet en main :

1. [getting-started.md](getting-started.md) : mettre en route l'environnement local, du clone au serveur qui répond, avec les variables d'environnement, les pièges connus et le dépannage.
2. [architecture.md](architecture.md) : la vue d'ensemble, les contextes bornés, le modèle de données temporel et géographique, les décisions structurantes.
3. [codebase-map.md](codebase-map.md) : où vit quoi dans l'arborescence, module par module, couche par couche, pour trouver rapidement le bon fichier.
4. [adding-a-feature.md](adding-a-feature.md) : la démarche concrète pour ajouter une fonctionnalité ou corriger un bug, du choix de l'issue à la pull request.
5. [testing.md](testing.md) : comment tester, la stratégie de tests, la couverture, et le setup de la suite bout en bout (Chrome/chromedriver).
